----- debug

For request 0989aa95-8fd7-4a09-b66f-2ee73c97a6d6, the orchestrator never received the plan. That UUID does not appear anywhere in its logs.
The orchestrator itself is currently healthy:
- Container: running.
- /vlm_robot_planner: present.
- /vlm_planner/ready: true.
- Other plans immediately before and after this failure were acknowledged and executed.
So this occurrence was loss of the one-shot injection message?not a lost ACK. The temporary publisher discovered the subscriber, published once, waited for an ACK, and exited. DDS graph discovery alone does not guarantee that the writer-reader connection is fully ready for reliable delivery.
How to check
Replace REQUEST_ID with the UUID from the error.
Check whether the orchestrator received it:
REQUEST_ID="0989aa95-8fd7-4a09-b66f-2ee73c97a6d6"

docker logs --since 30m vlm_ros2_real 2>&1 \
  | grep -C 5 "$REQUEST_ID"
Interpretation:
- No output: injection message never reached the callback.
- Plan acknowledgement ... accepted=True: plan was accepted; only the ACK was lost.
- accepted=False: it was explicitly rejected, usually because the node was busy or not ready.
Follow plan activity live:
docker logs -f vlm_ros2_real 2>&1 \
  | grep --line-buffered -E \
  "Plan acknowledgement|Injected plan|Task completed|task failed|Perception"
Check the orchestrator and readiness:
docker exec vlm_ros2_real bash -lc '
source /opt/ros/humble/setup.bash
source /workspace/ros2_ws/install/setup.bash

ros2 node list | grep /vlm_robot_planner
ros2 topic echo /vlm_planner/ready std_msgs/msg/Bool \
  --once \
  --qos-reliability reliable \
  --qos-durability transient_local \
  --qos-history keep_last \
  --qos-depth 1
'
Check injection and ACK endpoints:
docker exec vlm_ros2_real bash -lc '
